# VentaSync 多租户 SaaS 重构计划

## 1. 已确认的目标与首版范围

基于现有 VentaSync 业务逻辑，建设全新的 FastAPI + Vue 3 + MySQL 系统。

已确认的决策：

- 租户隔离：中心库 + 每租户独立业务库。
- 全新系统，不迁移历史业务数据。
- 平台管理员创建租户，并邀请租户负责人。
- 平台统一配置 Shopee 应用，租户授权连接自己的店铺。
- 首版包含租户权限底座及 Shopee 订单、库存闭环。
- 所有应用数据库表禁止使用外键，表和字段添加中文注释。

首版包含：登录、租户开通、成员与角色、数据范围、主商品及 SKU、Shopee 店铺授权、现有平台商品读取及映射、订单同步、库存变化、库存推送、任务记录、审计。

后续阶段再实施：完整商品刊登、价格营销、售后协商、平台发货和运单、结算对账、其他渠道、在线订阅支付、完整仓储和采购模块。

### 技术与工程组织

- `CUsersuserDesktopventasyncbackend`

后端按业务模块组织，采用 `Router → Service → Repository` 分层。事务由 Service 管理；API 与 Worker 调用相同业务服务；渠道连接器负责平台差异。

一期统一使用同步 SQLAlchemy Session。执行阻塞数据库操作的接口使用普通 `def`，每个请求和任务独立创建、关闭 Session。

## 2. 多租户与数据库设计

### 数据归属

一个租户代表一个经营主体，可以拥有多个成员和多个店铺。同一个用户可以加入多个租户，在不同租户拥有不同角色。

 数据位置  核心表组  职责 
---------
 中心库  `users`、`tenants`、`tenant_memberships`、`tenant_invitations`  全局身份、租户与成员关系 
 中心库  `tenant_databases`、`provisioning_jobs`  数据库路由、开通和迁移状态 
 中心库  平台角色及权限关联表  平台管理员授权 
 中心库  `plans`、`plan_features`、`subscriptions`  套餐、额度、有效期 
 中心库  `platform_channel_apps`、`channel_account_registry`  平台 Shopee 应用及外部店铺归属 
 中心库  `platform_audit_logs`  平台管理审计 
 租户库  `roles`、`role_permissions`、`member_roles`、`role_binding_scopes`  租户角色与数据范围 
 租户库  `tenant_settings`、`feature_settings`  公司设置、功能开关、权限版本 
 租户库  `products`、`product_skus`、图片及规格表  商品和可售 SKU 
 租户库  `stores`、`store_credentials`、`channel_listings`、`channel_listing_links`  店铺、令牌、平台商品及映射 
 租户库  `orders`、`order_items`、状态历史及平台原始数据表  统一订单及平台数据 
 租户库  `inventory_balances`、`stock_movements`、`order_stock_effects`  库存余额、流水及订单库存影响 
 租户库  `sync_schedules`、`sync_runs`、`webhook_events`、`outbox_events`  调度、任务、回调与事件投递 
 租户库  `files`、`audit_logs`、`idempotency_records`  文件、审计和请求防重 

租户业务表通过所在数据库隔离；跨租户日志、队列消息、缓存键、文件路径必须包含 `tenant_id`。

### 无外键规范

- SQLAlchemy 模型不声明 `ForeignKey`、`ForeignKeyConstraint`。
- Alembic 迁移和手写 SQL 不创建外键，不使用数据库级联删除。
- 关联字段使用普通 ID 列，按查询需求建立索引。
- 使用唯一约束保证业务唯一性，例如成员关系、租户内 SKU、店铺订单号、库存效果记录。
- 创建关联数据时，由 Service 验证关联对象存在、状态有效且属于当前授权范围。
- 删除优先采用停用或归档；确需物理删除时，由事务内业务代码明确处理关联数据。
- 不以关闭 `FOREIGN_KEY_CHECKS` 代替移除外键。
- 第三方组件附带的迁移同样需要检查，不直接执行带外键的迁移。
- 数据库验收查询 `information_schema.REFERENTIAL_CONSTRAINTS`，中心库及租户库均应为零条外键记录。

金额与汇率使用 `DECIMAL` 和 Python `Decimal`；时间存 UTC，按租户时区展示；大整数 ID 通过 JSON 字符串传给前端。

### 租户上下文与连接管理

请求必须先验证账号和租户成员关系，再构造不可变的 `TenantContext`，包含租户、成员、数据库路由和请求标识。

- 中心库和租户库使用不同的 Session 获取入口。
- 业务数据库名、服务器和凭据只从中心库受控映射读取。
- 未建立租户上下文时，业务查询直接失败。
- 不在共享连接上通过随意执行 `USE` 切换租户。
- Engine 按租户与连接版本缓存，设置池容量和闲置回收，控制总连接数。
- 运行账号限制访问对应数据库；建库与迁移使用独立运维身份。
- 不把“当前租户”保存在可被其他请求覆盖的全局变量中。

### 租户生命周期

首版支持 `provisioning`、`active`、`suspended`、`provision_failed`。

开通流程固定为：

```text
中心库登记租户
→ 创建业务库与受限账号
→ 执行租户迁移
→ 初始化设置、角色、默认库存地点
→ 发出负责人邀请
→ 标记 active
```

步骤可重试，失败不激活租户。邀请凭据有时效、只能使用一次且只存摘要。首次平台管理员由显式初始化命令创建，不开放公共管理员注册入口。

暂停租户后禁止租户业务访问和主动同步；已验签回调可暂存，但不改变库存。重新启用时先执行平台状态核对，再恢复推送。

首版由平台管理员配置套餐与额度，不实现在线购买。额度降低不删除已有数据，仅限制超额新增。

## 3. 身份、权限、API 与 Vue 行为

### 授权模型

采用：

```text
全局用户
→ 租户成员
→ 一个或多个角色绑定
→ 操作权限 + 绑定的数据范围
```

角色和权限集合存租户库，角色绑定引用中心库的成员 ID。写入绑定前验证该成员确属当前租户。

预置所有者、管理员、商品运营、订单运营、库存操作员、只读角色，租户可以复制和修改。所有者转移单独处理，禁止删除最后一个有效所有者。

功能权限使用明确编码，例如：

```text
catalog.product.read
catalog.product.create
catalog.product.update
catalog.cost.read
inventory.read
inventory.adjust
store.connect
order.read
order.sync
stock.push
member.invite
role.manage
role.assign
audit.read
```

一期数据范围支持：当前租户全部、指定店铺、指定库存地点。部门和组织树不纳入首版。

共享主商品管理权与店铺刊登资料权限分开。仅获得某店铺权限的成员，不能自动修改会影响全租户的主商品。

### 多角色计算规则

一次操作被允许，必须存在一个有效角色绑定，同时具有操作权限且覆盖目标数据。

例如“店铺 1 编辑权”加“全部店铺查看权”，只能编辑店铺 1，不能合成为全部店铺编辑权。

- 不同绑定的完整授权结果取并集，不拆开合并操作和范围。
- 同一绑定的多个店铺取并集，不同限制维度共同生效。
- 空范围代表没有授权，全部范围必须显式指定。
- 套餐限制、成员停用、租户暂停不能被角色绕过。
- 角色分配检查授予权限，防止通过编辑角色或调整范围自行提权。

列表、总数、搜索、详情、导出使用同一数据范围。敏感字段通过后端响应模型过滤，修改字段通过请求模型白名单控制。

权限修改同步递增权限版本；缓存键包含租户、成员及版本，后续请求和任务按当前版本重新检查。

### 登录与接口约定

Vue 后台采用同源 Cookie 会话认证：随机会话 ID、HttpOnly、Secure、CSRF Token、请求来源校验。Redis 保存会话，退出、账号停用和密码变更能够撤销会话。

 接口族  用途 
------
 `apiv1auth`  登录、退出、密码设置与重置 
 `apiv1me`  当前账号 
 `apiv1metenants`  当前账号可访问租户 
 `apiv1platform`  平台管理 
 `apiv1tenants{tenant_id}bootstrap`  当前租户、有效权限、功能开关 
 `apiv1tenants{tenant_id}members`、`roles`  成员与授权管理 
 `apiv1tenants{tenant_id}products`、`inventory`  商品和库存 
 `apiv1tenants{tenant_id}stores`、`orders`、`sync-runs`  店铺、订单、同步任务 
 `apiv1integrationsshopee`  授权回调和平台推送 

所有租户接口验证路径中的租户归属。平台回调通过独立签名与授权会话验证，不依赖普通用户会话，也不信任请求体中的租户 ID。

异步操作返回 `202` 和任务 ID，前端轮询任务详情。统一错误响应包含错误码、说明和 `request_id`；未登录返回 401，无操作权限返回 403，具体对象不可见返回 404，业务冲突返回 409。

### Vue 首版页面

实现登录、邀请激活、租户选择、平台租户管理、成员、角色与范围、商品、库存、店铺连接、平台商品映射、订单、任务记录、审计页面。

每个请求显式携带目标租户。租户切换时取消旧请求、清空旧数据和勾选状态、重新加载权限，并丢弃迟到的旧租户响应。不同浏览器标签页可以同时处理不同租户。

前端按钮和菜单根据有效权限显示；后端始终独立授权。界面以表格、筛选和操作为主，不添加占用大量空间的无效说明。

## 4. Shopee 订单与库存闭环

### 统一应用与店铺授权

平台管理员配置生产、测试环境的应用凭据，密钥加密保存或使用部署密钥引用。租户只执行店铺授权，不填写平台 Partner Key。

发起授权时生成一次性服务端授权会话，绑定租户、成员、应用环境及回调目标。回调核对会话后交换 Token，将店铺令牌保存到对应租户库。

中心库登记外部店铺归属；同一环境的同一 Shopee 店铺只允许归属一个有效租户。重新授权更新原连接，不重复创建店铺。

Token 刷新按店铺串行处理；失效后标记需要重新授权，暂停依赖该凭据的任务。

### 商品与订单

- 主商品与可售 SKU 分开；无规格商品同样拥有一个 SKU，避免两套库存写法。
- 读取店铺已有商品及规格，保存远端 ID，通过明确映射关联本地 SKU。
- SKU 自动匹配只接受唯一、明确结果；重复或缺失进入待处理列表。
- 平台订单先持久化原始数据，再归一化为统一订单和明细。
- 订单以店铺及平台订单号防重，保留价格、币种、成本和原始状态。
- 无法映射商品或状态的订单正常保存并标记异常，不猜测扣库存对象。
- 首版提供订单查询、同步和库存处理；平台发货、售后协商及完整商品发布列入后续阶段。

库存状态映射沿用现有项目的可配置扣减机制，初始映射从现有 Shopee 初始化配置提取。退款或退货通知不直接视为实物入库；首版由授权人员确认实际库存调整。

### 库存与任务可靠性

每个订单明细记录已经产生的库存影响，按“应扣数量减已扣数量”计算本次差额。

库存余额、流水、订单库存效果及待同步事件在同一个租户库事务中更新；相关行加锁并按固定顺序处理。外部平台请求在事务提交后执行。

外部已成立订单即使造成缺货也必须保存，负库存显示异常；推送平台的可售库存最低为零。人工调整禁止产生负库存。

使用 Outbox 投递后台任务，Worker 重新建立租户上下文。任务带租户、店铺、操作者、业务键，不能携带明文凭据。

- 手动任务执行前复核成员权限。
- 定时任务使用限定能力的自动化身份。
- 平台回调验签、防重后再处理，并重新获取必要的当前状态。
- 暂时性网络错误和限流采用有限重试；凭据失效或参数错误直接进入可处理失败状态。
- 库存推送按店铺与 SKU 串行，执行时读取最新库存，避免旧任务覆盖新数量。
- Redis 锁用于协调，最终防重依赖数据库记录和唯一约束。
- 队列与缓存 Redis 分开配置，清缓存不能清除待执行任务。

## 5. 实施顺序、验收与交付约束

 阶段  实施内容  验收结果 
---------
 P0：工程骨架  后端、Vue、配置、日志、API 约定、中心库与租户迁移骨架  能构建；新迁移不含外键，应用表与字段有中文注释 
 P1：身份与租户  平台管理员初始化、开通任务、邀请、登录、成员、数据库路由  两租户独立开通，一个用户可加入两家，失败开通可重试 
 P2：权限与页面框架  多角色、范围、字段过滤、权限版本、租户切换、审计  前后端一致授权，越权 ID、角色组合和迟到响应不能泄漏数据 
 P3：商品与库存  商品、SKU、图片、默认库存地点、调整、流水  SKU 映射清晰，重复请求和并发修改不重复或丢失数量 
 P4：Shopee 连接  平台应用配置、授权、刷新 Token、商品读取与映射  店铺归属唯一，凭据隔离，异常映射可人工处理 
 P5：订单库存闭环  拉单、回调、状态映射、库存效果、Outbox、库存推送  同一订单重复进入不重复扣库存，任务重试可恢复，远端库存可核对 
 P6：首版交付  任务页面、审计、额度、备份恢复、Docker 部署、试点验证  可独立开通、维护和暂停租户，完成真实店铺闭环验收 

验证只覆盖关键边界和业务结果：

1. 两租户存在相同商品、订单 ID 时，请求、缓存、文件、任务均不串租户。
2. “局部编辑 + 全局查看”不能获得全局编辑权。
3. 无成本权限的用户在查询和输出文件中都看不到成本。
4. 成员停用或权限撤销后，后续请求和未执行的手动任务不能越权。
5. 重复拉单、回调和重试不重复创建订单、扣减或恢复库存。
6. 两个订单同时影响一个 SKU 时，库存变化完整保留。
7. Worker 中断后能够恢复未完成工作；库存推送不能被旧值覆盖。
8. 中心库和全部租户库外键数量为零。
9. 单租户备份恢复不影响其他租户；恢复后先对账，再开启平台推送。

先使用脱敏固定响应验证平台适配，再用已获授权的测试店铺验证真实接口。平台应用审批、回调域名和店铺授权属于真实联调的外部前置条件；缺少时不能把模拟通过标记为真实验收通过。

实施遵守以下约束：

- 不擅自启动前后端项目或连接生产环境。
- 前端保留 `npm run dev`，提交前检查 `npm run build`。
- 后端保留 `app.mainapp` 入口，服务器通过 Docker 部署。
- 迁移使用独立发布任务执行，不由每个 API 副本启动时自动执行。
- 不执行原 Laravel 建表迁移；从新的无外键基线创建数据库。
- 无历史数据迁移、双写或旧系统在线切换任务。
- 首版按租户试点开放；真实平台推送默认关闭，完成店铺及 SKU 映射核对后再启用。
